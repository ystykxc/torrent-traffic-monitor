# 下载器流量统计（MoviePilot V3 插件）· v1.0.32

统计 MoviePilot 已接入下载器的上传/下载流量，支持定期通知。
由独立部署的 Docker 版 Torrent Traffic Monitor v50 整体迁移而来。

**作者：YST插件定制**

## 六、安装

1. 解压 `torrenttrafficmonitor_v1.0.32.zip`，得到 `torrenttrafficmonitor/` 目录。
2. 把整个 `torrenttrafficmonitor/` 目录放到 MoviePilot 的插件目录（容器内一般为
   `/moviepilot/app/plugins/`，或 `PLUGIN_LOCAL_REPO_PATHS` 指向的本地插件仓库）。
   目录名必须是类名的全小写 `torrenttrafficmonitor`，不要改动。
3. 重启 MoviePilot（或在插件市场使用「本地安装 / 上传 zip」），插件会出现在插件列表。
4. 启用插件，打开「配置」页完成设置；打开「插件详情」查看监控页面。

插件零额外 Python 依赖，仅使用标准库与 MoviePilot 自带的 `starlette` / `apscheduler`。

## 七、配置面板（单页）

| 行 | 控件 | 说明 |
| --- | --- | --- |
| 第 1 行 | 开关 + 下拉 | 启用插件（启动后台采集）、**采样间隔**（默认 1 分钟，可选 5 秒 ~ 30 分钟） |
| 第 2 行 | 开关 + 文本框 | 启用定时流量通知（**首次安装默认开启**）、五位 cron 通知时间（默认 `40 22 * * *`） |
| 第 3 行 | 多选 | 需要通知的流量统计时间范围（11 项多选，占满一行；默认今日 / 昨日 / 本周 / 本月） |
| 第 4 行 | 按钮 | **一键重新分配下载器颜色**（系统调色板重新分配） |
| 第 5 行起 | 开关 | 按宿主已接入下载器动态生成的启用停用开关，桌面一行三个、手机端顺序单列 |

所有控件使用 MoviePilot 原生 Vuetify 组件，单页平铺、无提示信息、无重复设置。
v1.0.4 起桌面端按上面五行顺序排布（下载器开关一行三个），手机端沿用同一顺序、
每个控件占满一行。
下载器实时速率 / 在线状态固定 5 秒采样，**不在配置页提供任何外显设置**。
下载器连接信息自动读取 MoviePilot 已接入配置，无需也不能在插件里增删改；
本地只保存 `dkey`、颜色、启用停用与统计表，密码等连接信息不落盘。

## 九、定期通知

在插件「配置」页：

- 开关「启用定期流量通知」——**首次安装默认开启**，默认 cron `40 22 * * *`（每天 22:40），
  默认通知范围为**今日 / 昨日 / 本周 / 本月**；保存过配置后以保存值为准；
- 填写**五位 cron 表达式**（分 时 日 月 周），例如 `40 22 * * *` 表示每天 22:40；
- 在**多项选择列表**中勾选需要通知的时间范围（覆盖流量统计卡片全部 11 个可选范围：
  1小时 / 6小时 / 12小时 / 今日 / 昨日 / 本周 / 上周 / 本月 / 上月 / 本年 / 全部）；
- 保存后由 MoviePilot 重载插件服务生效。

**所有勾选范围汇总在一条通知里**，范围之间用 24 格横线分隔；每个范围是「标题 +
无表头明细表」一段纯文本（标题下方无横线）。通知为纯文本、没有表格语法，每列按
**显示宽度**补齐（中文 / emoji 记 2 格）、数值列右对齐，列间用可见的 `|` 与 `+---+`
画线隔开（不使用制表符，避免被客户端吞掉后整行粘连）：

```
今日流量统计（2025-11-15）
+------------+----------------+--------------+
| 合计       |    🟢↑ 1.01 TB |  🔴↓ 2.56 TB |
| QB-01      |    🟢↑ 8.10 GB | 🔴↓ 40.00 GB |
| TR-01      |    🟢↑ 4.24 GB | 🔴↓ 16.78 GB |
| 群晖下载器 | 🟢↑ 1023.50 GB |  🔴↓ 2.50 TB |
+------------+----------------+--------------+

────────────────────────

本周流量统计（2025-11-11 ~ 2025-11-18）
+--------+----------------+---------------+
| 合计   | 🟢↑ 88.00 GB   | 🔴↓ 300.00 GB |
| QB-01  | 🟢↑ 61.00 GB   | 🔴↓ 210.00 GB |
| TR-01  | 🟢↑ 27.00 GB   |  🔴↓ 90.00 GB |
+--------+----------------+---------------+
```

- 每段第一行：时间范围名称 + 「流量统计」+ 具体自然时间段或日期备注；标题下方
  **不再有横线**，紧跟无表头明细表（v1.0.29 删除了 v1.0.28 的标题等长横线）；
- 标题下方紧跟无表头明细表：先「合计」行，再各下载器行；
- 上传数值前加 **🟢↑**、下载数值前加 **🔴↓**（圆点后带文本箭头 ↑ / ↓），数值本身
  不带「上传」「下载」文字；
- 列宽按本段最长内容自适应，边框长度随之变化；
- 段间横线固定 **24 格**（与 v1.0.27 一致）；
- 数据口径与页面卡片完全一致（复用同一套 `chart.build`）。

## 十、数据口径

- 流量只取下载器**累计计数器**（qBittorrent `alltime_dl/alltime_ul`、Transmission
  `cumulative-stats`）的单调差值，不用瞬时速率积分估算。
- 采集线程固定 5 秒刷新一次快照（实时速率 / 在线状态，纯内存）；到达
  「采样间隔」（默认 1 分钟）才记一次账。跨多个 5 秒轮次的累计增量一次性
  记账，差值仍等于整段采样间隔的流量，不丢账。
- 一次采样增量按时间比例分摊到起止两个小时桶，保证跨小时不错账。
- 只物化一层 `hourly` 小时桶，日/周/月/年均从它聚合，五种粒度对得上账。
- 数据保存在插件数据目录 `traffic.db`（SQLite），不含插件启用前的历史流量。

## 十一、实现说明

- 后端：`__init__.py` 为主类，实现 `init_plugin` / `get_form` / `get_page` /
  `get_api` / `get_service` / `stop_service`；`core/` 为采集、统计、图表、通知模块。
- 前端请求统一收敛到 `/data?action=...&args=...&apikey=...` 单端点；
  `page()` 把 CSS/JS 内联进 HTML，页面自包含、不依赖宿主静态资源路由。
- 配置页「一键重新分配颜色」按钮由 V3 前端 `FormRender` 渲染：按钮的
  `props.onClick` 是一段函数代码字符串，在浏览器里执行并 `fetch` 插件自身
  `/data?action=downloaders/recolor` 端点（后端调用 `db.recolor_all()`）。
- 下载器连接信息每次由 `DownloaderHelper().get_configs(include_disabled=True)`
  实时读取。
